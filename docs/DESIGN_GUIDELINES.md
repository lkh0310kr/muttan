# muttan 디자인 가이드

## 1부. 화면에 적용하는 규칙

### 문구와 타이포그래피

- 일반 UI는 짧고 자연스러운 한국어로 작성한다. 영문이 필요하면 sentence case를 사용하며 `AUTO`, `STANDARD`, `IN TUNE`처럼 단어 전체를 대문자로 만들지 않는다. `.uppercased()`로 UI 문구를 변환하지 않는다.
- 음·코드의 표준 기호인 `E2`, `C`, `Am`, `A7`, 튜닝의 `D`, 단위 `Hz`는 의미를 유지한다. 음이름을 소문자로 바꾸어 코드의 장·단조 표기와 혼동시키지 않는다.
- 상태는 행동과 연결한다. 예: `튜너 시작`, `개방현을 연주하세요`, `음정을 조금 낮추세요`. 과장된 칭찬이나 의미 없는 응원 문구를 넣지 않는다.
- 시스템 글꼴과 의미 기반 크기를 쓴다. 큰 음이름 외에는 숫자·라벨에 모두 둥근 굵은 글꼴을 쓰지 않는다. 한국어에 자간 확대를 적용하지 않는다.

### 정보와 조작

- 튜너의 순서는 튜닝 선택 → 목표 음과 편차 → 현 선택 → 시작/중지다. 코드 사전은 검색 → 필터 → 운지 확인 순서를 따른다.
- 상태에 따라 바뀌는 값과 고정 안내를 구분한다. 음정 편차는 센트 숫자와 중심 눈금으로 보여준다. 실제 시간 이력을 표시하지 않는 화면에는 시간 그래프처럼 보이는 격자를 그리지 않는다.
- 카드와 배경은 콘텐츠를 묶을 때 사용한다. 모든 텍스트를 캡슐·배지 안에 넣거나 같은 내용을 여러 카드로 반복하지 않는다.
- 실제 동작이 연결되지 않은 항목을 작동하는 버튼처럼 추가하지 않는다. 설정 프로토타입은 별도 기능 작업에서 실제 동작과 함께 정리한다.

### 색상과 간격

- 배경·텍스트·구분선은 시스템 의미 색상을 우선한다. 강조색은 하나의 청록 계열로 통일한다.
- 라이트 모드 강조 문자는 짙은 청록, 다크 모드는 밝은 민트를 사용한다. 밝은 민트 위의 글자는 어두운 색을 사용한다.
- 선택·정상 상태를 색만으로 전달하지 않는다. 선택 외곽선, 음이름, 상태 문구를 함께 표시한다.
- 간격은 8·12·16·24pt를 기본으로 한다. 모서리 반경은 역할에 맞추고, 큰 반경과 그림자를 모든 요소에 반복 적용하지 않는다.
- 그라데이션은 금속·목재 같은 재질의 방향성을 설명할 때만 약하게 쓴다. 장식용 글로우, 다색 배경, 읽기를 방해하는 질감은 넣지 않는다.

### 기타 그림의 구조

- 헤드스톡은 매끈하게 좁아지는 외곽, 좌우 각 3개의 튜닝 키, 포스트, 너트, 짧은 넥으로 구분한다. 잘록한 곡선을 반복한 장식 실루엣을 사용하지 않는다.
- 앞면 기준 포스트 순서는 왼쪽 아래부터 `6 → 5 → 4`, 오른쪽 위부터 `3 → 2 → 1`이다. 현 선택 버튼의 높이는 해당 포스트에 맞춘다.
- 너트의 6개 홈은 왼쪽부터 6번→1번 현이다. 각 줄은 넥에서 너트까지 평행하게 이어지고, 너트에서 자신의 포스트까지 연결된다. 서로 다른 줄이 교차하거나 포스트 뒤로 공중에 끝나지 않아야 한다.
- 줄 굵기는 저음현에서 고음현으로 가늘어진다. 선택한 현만 강조색으로 표시한다. 선택한 버튼과 줄은 동일한 현 ID로 연결한다.
- 기타 그림의 모든 좌표는 같은 정규화된 구조에서 계산한다. 버튼 배치와 그림에 별도의 포스트 좌표를 중복 정의하지 않는다.

### 검토와 캡처

- 라이트/다크, 대기/감지 상태에서 음정 표시와 선택한 줄이 읽히는지 확인한다.
- 코드/현 기호, 숫자, 뮤트·개방현, 너트·줄 연결처럼 도메인 정확성을 먼저 확인한다.
- 코드 목록·상세·튜너·설정 캡처를 갱신하고 변경한 화면을 실제 크기로 확인한다. 그림 구조 변경은 좌표와 연결 관계도 검사한다.
- 비슷한 카드, 그라데이션, 시스템 글꼴 자체를 AI 생성의 증거로 판단하지 않는다. 해당 요소가 이 화면의 조작·정보·악기 구조를 설명하는지를 판단한다.

## 2부. 조사 근거와 참고 자료

### AI slop의 의미와 적용 범위

Merriam-Webster는 slop을 AI로 대량 생성되는 낮은 품질의 디지털 콘텐츠라는 의미로 정의한다. 이것은 UI의 특정 색이나 글꼴을 판정하는 기술 표준이 아니다. 이 앱에서는 **검증되지 않은 기타 그림, 읽기 어려운 문구, 기능과 무관한 장식, 도메인 구분 없이 반복되는 템플릿**을 줄이는 작업 기준으로 적용한다. [정의](https://www.merriam-webster.com/dictionary/slop)

CHI 2024의 시각적 발상 실험(N=60)은 AI 이미지 지원 그룹에서 초기 예시에 대한 고착이 증가하고 아이디어의 다양성이 감소한 결과를 보고했다. 시각 발상 과제의 결과이므로 모든 앱 디자인이나 모든 AI 사용의 효과로 일반화하지 않는다. 참고 이미지는 하나를 복제하기보다 실제 악기 사진과 기능 화면을 교차 확인한다. [연구 논문](https://arxiv.org/abs/2403.11164)

Apple은 사용자에게 익숙하고 명확한 표현, 일관된 언어 패턴과 대소문자 규칙을 권장한다. 위 1부의 한국어 우선·전체 대문자 금지는 사용자 요청을 반영한 **muttan의 제품 규칙**이다. Apple이 모든 앱의 대문자 사용을 금지한다는 의미는 아니다. [Apple 글쓰기 지침](https://developer.apple.com/design/human-interface-guidelines/writing)
